# 数独配置表字段说明

> 文件位置：`assets/resources/config/sudoku.json`
> 加载方式：游戏启动时由 `core/Config.ts` 通过 resources 自动加载，按 `id` 索引
> 生效方式：关卡表（level.json）里把某一关指向某个 id，进入该关即读取该行数据

---

## 一、字段一览

| 字段 | 类型 | 可填值 | 说明 |
|---|---|---|---|
| `id` | string | 自定义唯一标识，建议 `su_<类型>_<难度>` | 配置行唯一 id，关卡表通过它引用本行 |
| `type` | number | `4` / `6` / `9` | 数独类型：4=四宫格(2×2宫)、6=六宫格(2×3宫)、9=九宫格(3×3宫) |
| `difficulty` | string | `简单` / `普通` / `困难` | 难度名，用于界面展示与难度统计 |
| `timeCostStar` | number[] | 秒数数组，升序，如 `[60,100,200]` | **超时扣星阶梯**：用时每达到一个阈值扣 1 颗星 |
| `errorCostStar` | number[] | 次数数组，升序，如 `[1,3,6]` | **错误扣星阶梯**：累计错误每达到一个阈值扣 1 颗星 |
| `holes` | number | 整数（建议 ≤ 总格数-类型格数） | 挖空数量：出题时挖掉的格子数，越大越难 |
| `rewardCoins` | number | 正整数 | 通关金币奖励（与剩余星数无关，通关即给） |

---

## 二、扣星规则（数组阶梯语义）

开局 3 颗星，**超时**和**错误**分别按各自数组的阈值阶梯扣星，达到一个阈值扣 1 颗；两类合计最多扣 3 颗。

```
剩余星 = 3 − 超时达到的阈值个数 − 错误达到的阈值个数（最低 0）
```

**示例**：`"timeCostStar": [60, 100, 200]`、`"errorCostStar": [1, 3, 6]`

| 事件 | 扣星 |
|---|---|
| 用时达到 60 秒 | 扣第 1 颗星 |
| 用时达到 100 秒 | 扣第 2 颗星 |
| 用时达到 200 秒 | 扣第 3 颗星 |
| 累计错误 1 次 | 扣第 1 颗星 |
| 累计错误第 3 次 | 扣第 2 颗星 |
| 累计错误第 6 次 | 扣第 3 颗星 |

- 数组有几项就最多扣几颗（简单难度可只配 1 项 `[60]`，即只会因超时扣 1 颗）
- **星数扣到 0 → 直接失败结算**（弹窗：再来一次 / 退出），失败不保存进度、不发奖励
- 胜利结算按剩余星展示（最多 3 颗）；填满全盘且无冲突即胜利

## 三、错误判定方式

按数独**规则冲突**判定（不是对照答案）：玩家填入数字后，该数字与所在行/列/宫内已有数字重复 → 该次填入计 1 次错误，相关格子红显。玩家可以重新点该格填其他数字改正。

---

## 四、完整示例

```json
[
    { "id": "su_4_easy",   "type": 4, "difficulty": "简单", "timeCostStar": [60],            "errorCostStar": [1],        "holes": 6,  "rewardCoins": 20 },
    { "id": "su_6_normal", "type": 6, "difficulty": "普通", "timeCostStar": [90, 180],       "errorCostStar": [2, 5],     "holes": 16, "rewardCoins": 40 },
    { "id": "su_9_hard",   "type": 9, "difficulty": "困难", "timeCostStar": [100, 200, 300], "errorCostStar": [2, 4, 6],  "holes": 48, "rewardCoins": 80 }
]
```

挖空数参考区间：4 宫格 6~11（总 16 格）、6 宫格 12~20（总 36 格）、9 宫格 36~48（总 81 格）。

## 五、关卡表 level.json（关联玩法与配置）

文件：`assets/resources/config/level.json`。数组每行把某一关指向某玩法某配置：

```json
[
    { "id": "L0-0", "chapter": 0, "level": 0, "game": "sudoku", "cfgId": "su_4_easy" },
    { "id": "L0-5", "chapter": 0, "level": 5, "game": "mine",   "cfgId": "" }
]
```

| 字段 | 说明 |
|---|---|
| `id` | 行唯一 id（自定义，如 `L<章>-<关>`） |
| `chapter` | 章节序号（0 起） |
| `level` | 关卡序号（0 起，0 即第 1 关） |
| `game` | 玩法：`sudoku` / `mine` / `star` / `shikaku` / `killer` |
| `cfgId` | 该玩法配置表中的行 id；非数独玩法暂填 `""` |

> 未在表中配置的关卡走默认轮换（玩法轮换 + 数独按章节渐进难度）。表里配了就以表为准。
> 挑战模式固定映射：每日=`su_4_easy`、每周=`su_6_normal`、每月=`su_9_hard`。

---

## 六、后续扩展规范

- 每个新玩法一张表：`mine.json` / `star.json` / `shikaku.json` / `killer.json`，同样按 `id` 索引
- 新玩法表建议都含 `difficulty`（简单/普通/困难）与 `rewardCoins`（通关奖励），保证结算与展示一致
- 加字段只需：① 表里加字段 ② `core/Config.ts` 的对应 interface 加声明 ③ 玩法逻辑读取
